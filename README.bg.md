# Лична библиотека (LLM Wiki)

[English](README.md) · Български · [Страница за продукта](https://cecosd.github.io/llm-wiki/)

Разработен от **SDevelopers LTD (ЕсДевелопърс ЕООД)** съвместно с **Claude**. Продуктът не е издаден и одобрен от Anthropic.

Локална база знания за книги, статии, таблици и бележки, изградена по модела на Andrej Karpathy (Karpathy, 2026; Boudro, 2026). Ти подбираш какво влиза; Claude Code чете, обобщава, свързва и поддържа wiki-то. Не е вързана за тема: работи за всякакви текстове.

## Как работи

```
 raw/inbox/  ──npm run inbox──▶  raw/books, papers, articles, data…   (оригиналите, не се променят)
                                        │
                                 npm run extract
                                        ▼
                                 raw/.extracted/*.md                    (текст за четене от агента)
                                        │
                                 Claude Code: /wiki-ingest
                                        ▼
            wiki/sources · concepts · entities · topics · questions     (поддържа се от агента)
                     index.md (каталог)   log.md (дневник)
                                        │
             /wiki-query  ·  /wiki-lint  ·  npm run serve  ·  Obsidian
```

Три слоя: `raw/` (оригинали), `wiki/` (генерирани страници), `CLAUDE.md` (схемата, която казва на агента как да работи). Три операции: ingest, query, lint.

## Обновяване

Страницата **„Настройки → Обновления“** (`#/settings/updates`) проверява с един бутон дали в GitHub има нова версия на кода и кои пакети са остарели; нищо не се инсталира само.

- **„Обнови до X“** до всеки пакет и **„Обнови всички безопасни“** пускат `npm update` с `--ignore-scripts`, само за пакетите от `package.json` и само до версиите, които той позволява. После библиотеката се пуска отново сама и страницата се презарежда.
- **Основните версии** (например 2.x, когато е позволено 1.x) не се инсталират от бутона: показват се като команда за копиране, защото може да променят поведението и трябва да се пуснат с `npm test` след тях.
- **В изолацията** (`npm run serve:safe`, прекият път в WSL) `node_modules/` е само за четене, затова npm го пуска стартерът отвън. Ако библиотеката не тръгне с новите версии до 30 секунди, той връща предишните (`npm ci`). Подробности в [SECURITY.md](SECURITY.md).
- **Без изолация** рестартът става сам само при пускане с прекия път или с `scripts/launch/wsl-start.sh`. При `npm run serve` в терминал страницата казва да спреш библиотеката (`Ctrl+C`) и да я пуснеш отново, за да се заредят новите версии.

Продуктът работи добре, но стои върху библиотеки на Node.js със свои зависимости, затова версиите и уязвимостите трябва да се проверяват редовно (`npm outdated`, `npm audit`, след обновяване `npm test`). Кодът се обновява с `git restore CLAUDE.md .claude wiki/_templates scripts/starter`, `git pull`, `npm install` и `npm run content -- bg` (езиковият пакет презаписва няколко следени файла, затова първата команда ги връща). Твоите страници, `raw/`, чернови и настройки не са в репото (виж „Данните ти остават извън репото“), така че обновяването не ги засяга. Преди обновяване можеш да направиш запис в собственото си хранилище: `git add -A && git commit -m "Преди обновяване"`.

## Първоначална настройка

Изисквания: Node.js 20+, Claude Code, по желание Git, Obsidian и `pdftotext` (poppler).

**На компютър, на който нищо не е инсталирано:** изтеглете репото (зеленият бутон Code, после Download ZIP, или `git clone`) и пуснете инсталатора. Той проверява Node.js, библиотеките, Claude Code и входа в акаунта, пита преди да инсталира липсващото, после стартира библиотеката и я отваря в браузъра:

- Windows: двоен клик на `install.cmd`
- macOS, Linux, WSL: `./install.sh`

Всички стъпки са изброени и на страницата **Инсталация** в приложението (`#/setup`), с точната команда за вашата система. Инсталаторът иска интернет, а за акаунта в Claude: абонамент (Pro или Max) или API ключ на Anthropic. Съобщенията му са на английски, защото езикът на библиотеката още не е избран.

Ако предпочитате ръчно:

```bash
git clone <адрес на това репо> llm-wiki
cd llm-wiki
npm install
claude          # вход, веднъж
npm run serve   # http://localhost:4321
```

`pdftotext` дава по-добър текст от PDF (пази колоните и номерата на страниците). Без него скриптът използва `unpdf` (вграден pdf.js).
- macOS: `brew install poppler`
- Windows: `winget install oschwartz10612.Poppler` или `choco install poppler`
- Linux: `sudo apt install poppler-utils`

## Ежедневна работа

Пусни интерфейса с `npm run serve` и отвори http://localhost:4321. Терминал е нужен само за това.

1. **Качи:** пускаш файлове в полето на началната страница (или ги копираш в `raw/inbox/`).
2. **Подреди:** натискаш „Подреди и извлечи текста“.
3. **Обработи:** Claude започва сам (превключвателят „Обработвай автоматично след подреждане“). Или натискаш „Обработи с Claude“. Виждаш на живо какво чете и коя страница пише.
4. **Разглеждай:** страниците се появяват сами, без презареждане.

### Обработка с бутон: как работи

Сървърът на библиотеката пуска Claude Code във фонов режим (`claude -p`) със същите инструкции (`CLAUDE.md`) и скилове, както в терминала. Използва абонамента, с който си влязъл в Claude Code, затова е нужно **веднъж** да пуснеш `claude` в терминал и да влезеш.

- **Акцентът идва от книгата.** Claude не спира да пита. Сам определя акцента по заявената цел на автора, най-развитите глави и централното понятие, и записва обосновката в страницата.
- **Един файл наведнъж.** При изчерпан лимит на абонамента опашката спира и чака бутона „Продължи“.
- **Тесни права.** Claude може да чете, да пише **само** в `wiki/` и да пуска **само** скриптовете на библиотеката (`npm run pending`, `extract`, `lint`…). Всичко друго се отказва автоматично.
- **Точка за връщане.** Преди всяка обработка се прави git запис. Бутонът „Върни“ връща wiki-то отпреди последната обработка, а файлът отново става „чака обработка“.
- **Без половинчати страници.** Ако спреш обработката, тя се провали или удари лимита, започнатото се връща автоматично.

### Режими: колко от лимита да харчиш

В панела за обработка избираш режим. Скъпото е четенето на стотици страници, а не преценката, затова режимите разделят тези две работи (Anthropic, 2026a, 2026b).

| Режим | Кой чете | Кой редактира | За какво |
|---|---|---|---|
| **Икономичен** (по подразбиране) | подагентът `chapter-reader` на Haiku, ниско усилие | Sonnet | много книги наведнъж |
| **Балансиран** | Sonnet | Sonnet | когато Haiku пропуска нюанси |
| **Най-добър** | Opus | Opus | ключови книги |

- „Синтезът винаги с най-силния модел (Opus)“ е включено по подразбиране: чете само страниците, затова е рядък и евтин, а там преценката е най-ценна.
- Режимът се записва с всяка обработка в историята, за да сравняваш резултатите.
- Документацията не дава точно колко лимит спестява всеки модел, така че провери сам: **пилот с една книга**. Обработи я в Икономичен, натисни „Върни“, обработи я в Най-добър и сравни двете версии на страниците (глави, ключови идеи със страници, понятия). Ако Икономичният пропуска нюанси, мини на Балансиран.
- Четецът е в `.claude/agents/chapter-reader.md`; можеш да смениш модела му (`model: haiku`) с `sonnet`.

### Други модели: API, локален модел, безплатен чат

**Настройки → Модел** избира кой обработва библиотеката. Бутоните и текстовете следват името на модела („Попитай Gemini“, „Обработи с Ollama“), а всеки надпис може да се смени отделно за всеки модел.

| Начин | Доставчици | Как работи |
|---|---|---|
| **Агент с инструменти** | абонамент за Claude, API ключ на Claude, DeepSeek, локален Ollama 0.14+, всеки адрес, съвместим с Anthropic | Claude Code както досега; за друг доставчик получава `ANTHROPIC_BASE_URL` и трите модела (Anthropic, n.d.; DeepSeek, n.d.; Ollama, n.d.) |
| **Без инструменти** | OpenAI, Google Gemini (безплатен или платен ключ), Groq, OpenRouter, DeepSeek, Mistral, Claude API, Ollama, LM Studio, всеки адрес с `/chat/completions` | Сървърът подава текста на модела глава по глава и сам пише страниците по шаблоните, затова работят и малки локални модели (Google, n.d.-c) |
| **Копиране и поставяне** | всеки чат в браузъра, включително безплатен акаунт | Всяка стъпка е заявка, която копираш в чата; отговора поставяш обратно |

Ключовете се пазят в `.library-secrets.json` (извън git, четим само от теб, затворен за агента) или идват от променлива на средата. Безплатните нива може да ползват съдържанието за обучение: не пращай там лични материали. Страница, обработена от слаб модел, може да се надгради по-късно с по-силен („Надгради“). Всеки профил в „Настройки → Модел“ има кратък списък „Какво се случва и защо“ със стъпките на настройката.

#### Gemini: безплатен или платен ключ

Ключът принадлежи на проект в Google AI Studio, а проектът определя нивото (Google, n.d.-a; Google, n.d.-d):

| | Безплатно ниво | Платено ниво |
|---|---|---|
| Профил в „Настройки → Модел“ | „Google Gemini, безплатно ниво (проект без платежна сметка)“ | „Google Gemini, платен (проект с платежна сметка)“ |
| Проект | не е свързан с платежна сметка | свързан с платежна сметка; новите сметки плащат предварително (Prepay, поне 5 USD) |
| Модели | Flash и Flash-Lite; Pro и Gemini 4 Argon нямат безплатно ниво (Google, n.d.-b) | всички |
| Лимити | на минута и на ден, за всеки проект и модел, виждат се само в AI Studio (Rate limits); дневните се нулират в полунощ тихоокеанско време (около 10:00 българско време) | по-високи, с месечен таван на разходите според нивото на сметката |
| Съдържанието ти | използва се за подобряване на продуктите на Google | не се използва |

- **Грешка 402 „Your prepayment credits are depleted“.** Ключът е от проект, свързан с платежна сметка без кредит. Такъв проект взима платеното ниво на сметката и не се връща на безплатното при 0, затова спират всички ключове на сметката. Добави кредит в AI Studio (Billing) или създай проект без платежна сметка и вземи ключа оттам (Google, n.d.-a).
- **Платен акаунт в Gemini.** Ключът му се слага в платения профил, който носи цените на Google, затова оценката показва сума (цените могат да се сменят). Абонаментът Google AI Pro или Ultra за приложението Gemini сам по себе си не дава API ключ, но включва месечни кредити за Google Cloud (10 USD при AI Pro), които важат за Gemini API, след като ги активираш в Google Developer Program (Google, 2026).
- **Колко заявки.** Една книга иска приблизително по една заявка на глава плюс 5 до 10. Лекият модел (Flash-Lite) чете главите, а средният (Flash) пише страниците, така че лимитите на двата модела се харчат поотделно. Когато дневният лимит свърши, опашката чака нулирането и започва този източник отначало.

#### Groq: безплатен ключ

Groq е бърз, но безплатният му план брои токени, не само заявки.

- **Модели.** Списъкът на Groq смесва модели за текст с модели за реч (Whisper, Orpheus) и за проверки за безопасност (Prompt Guard, Safeguard) (Groq, n.d.-d). Страници пишат само моделите за текст, затова „Зареди моделите“ скрива другите, а ако някой от тях е в поле, излиза предупреждение. Профилът чете главите с `openai/gpt-oss-20b` и пише с `openai/gpt-oss-120b`; Llama 3.x е спрян за безплатния план на 16 август 2026 (Groq, n.d.-b).
- **Лимити.** Таблицата с лимити на Groq дава на тези модели 30 заявки и 8000 токена на минута и 1000 заявки и 200 000 токена на ден, за всеки модел (Groq, n.d.-c). Страницата не казва ясно за кой план е таблицата, а колоната за плана Developer на страницата с моделите е много по-висока (250 000 токена на минута; Groq, n.d.-d), затова провери своите числа на страницата с лимитите в конзолата на Groq (връзката „Твоите лимити“ в „Настройки → Модел“).
- **Какво следва от това.** Една заявка трябва да се побере в лимита на минута, затова профилът задава контекст 7000 токена и сървърът праща кратки части. Една книга иска повече токени, отколкото дава един ден: оценката предупреждава, преди да започнеш, а задача, стигнала дневния лимит, чака колкото каже Groq и после започва този източник отначало. Ползвай безплатния план за статии и кратки текстове и очаквай да е бавно: една заявка взима почти целия лимит на минута, така че минава около една в минута (глава от 6500 думи иска около 15 до 20).
- **Грешки.** Модел за реч отговаря „does not support chat completions“, а някои модели първо искат да приемеш условията им в конзолата на Groq; и двете дават ясно съобщение. Твърде голяма заявка е грешка 413 (Groq, n.d.-a). Моделите gpt-oss мислят преди отговора и харчат за това част от лимита за изход, затова профилът ги кара да мислят кратко, а отговор, отрязан на лимита, се иска пак с повече място. „Опитай връзката“ праща по една кратка заявка към всеки избран модел, така че грешен модел се вижда, преди да се прати цял текст.

### Ако индексът, дневникът или обзорът са празни или загубени

`wiki/index.md`, `log.md` и `overview.md` могат да се изградят наново по всяко време от страниците, без да се чете нищо от книгите и без да се харчи от лимита. Страниците „Индекс“, „Дневник“ и „Обзор“ имат бутон **„Изгради наново“**; от терминала `npm run index` (`-- --only index|log|overview`, `-- --dry` за проба).

| Файл | Какво се случва |
|---|---|
| `index.md` | Изгражда се изцяло от страниците. Описанията от стария индекс се запазват, за новите се взема първото изречение или акцентът на източника |
| `log.md` | Съществуващите записи се запазват. За източници, които не се споменават в него, се добавят **възстановени записи** (дата от `created`, `upgraded`). Не може да се върне точното съдържание на изгубени записи (кои понятия са обновени, какви противоречия са отбелязани): за това е git |
| `overview.md` | Автоматичен блок (числа, теми, най-свързани понятия, източници) между маркери `auto-overview`. Текстът извън блока, твой или на Claude, не се пипа. За разказ как темите се свързват пусни „Синтез между книгите“ |

Старите версии се копират в `outputs/backup-*`, а „Върни“ на началната страница връща предишното състояние.

### Премахване на източник

Ако си изтрил оригинала от `raw/` нарочно, страницата на източника показва „Оригиналният файл липсва“. Най-долу на страницата на всеки източник има бутон **„Премахни източника…“**. Преди да потвърдиш, виждаш колко страници се махат и колко се чистят.

- Махат се страницата на източника, главите му и текстовата версия в `raw/.extracted/`.
- Цитатите към него в понятията и личностите се изчистват (`([[книга-ch02]], с. 36)` изчезва, а останалите цитати в същата скоба се запазват). Изчистват се и редовете в `index.md`, и връзките в `sources` и `related`.
- Понятия, които са се опирали **само** на тази книга, не се трият, а се показват като „остават без източник“, за да ги прегледаш.
- Страниците на източника (с твоите „Мои бележки“) се архивират в `outputs/removed/`.
- „Върни“ на началната страница връща wiki-то. Текстовата версия в `.extracted` не се възстановява, защото оригиналът го няма.
- От терминала: `npm run remove` (списък на източниците без оригинал), `npm run remove -- <слъг>` (преглед), `npm run remove -- <слъг> --apply`.

### Drill down: от книгата до самата страница

```
Книга   →   Глава   →   „с. 53“   →   текстът на страница 53 (и бутон за PDF на нея)
```

- Книгите се разделят на **глави**: всяка има обобщение, ключови идеи и понятия. Страницата на главата показва предишна и следваща глава.
- Всяко **„с. N“** е връзка: отваря четец отстрани с текста на тази страница. Със стрелките ← → прелистваш, а бутонът отваря PDF-а точно там. Четецът показва и печатния номер на страницата, ако се различава от номера в PDF.
- На страницата на всяко **понятие** „Сочат насам“ групира главите под книгата им. Така от понятието стигаш до точното място във всяка книга.
- За книги, обработени преди тази версия: на страницата на книгата има бутон **„Раздели по глави“**.

### Надграждане на старите източници и синтез

Източниците, обработени преди тази версия, са отбелязани на началната страница: „N източника са обработени по стария начин“.

- **„Надгради всички“** ги чете наново, глава по глава, **без да започва отначало**: добавя акцент, глави, точни страници за четеца, пропуснати понятия и противоречия с другите книги. Нищо не се дублира, а „Мои бележки“ се пренасят дословно. Редът е по важност: първо книгите, към които сочат най-много страници.
- **Преди всеки източник** сървърът извлича текста наново и проверява дали има какво да се чете. Сканираните книги (под 15 думи на страница) се отделят **без да се харчи от лимита**. Те се разпознават автоматично с **вградения OCR** (tesseract.js с български и английски език, идва с `npm install`, работи офлайн, без външни програми). Ако имаш и [`ocrmypdf`](https://ocrmypdf.readthedocs.io) с български език, ползва се той, защото е по-бърз. Вграденият е по-бавен: за книга от 300 страници очаквай десетки минути, затова оставяй сървъра пуснат.
- **При изчерпан лимит** опашката изчаква и опитва отново на всеки 30 минути, докато сървърът работи. При много книги на по-малък абонамент очаквай няколко дни; просто остави `npm run serve` пуснат.
- **„Синтез между книгите“** чете само страниците, не книгите: прави сравнения между авторите по общите им понятия, тематични хъбове, нов обзор и отчет с празнините в `outputs/`. Най-пълен е след надграждането.
- Отделна книга се надгражда и от нейната страница, с бутона „Надгради“.

## Езици (интерфейс)

Интерфейсът и съобщенията на сървъра са на **български** и **английски**. Езикът се избира в страничната лента; при първо отваряне се взема езикът на браузъра.

**Нов език на интерфейса се добавя без промяна в кода.** Преводите са във файлове `locales/<код>.json`:

```json
{
  "_meta": { "code": "de", "name": "Deutsch" },
  "messages": {
    "Search": "Suche",
    "{0} pages · {1} files": "{0} Seiten · {1} Dateien"
  }
}
```

1. Копирай `locales/en.json` като `locales/<код>.json` (например `de.json`).
2. Смени `_meta` (`code` е името на файла, `name` се показва в менюто за език).
3. Преведи стойностите. Ключовете са английските текстове и не се променят; пази `{0}`, `{1}` в превода.
4. Пусни `npm run i18n:check`: показва липсващите ключове и несъвпадащи `{0}`. Липсващ превод не е грешка: показва се английският текст.
5. Презареди страницата: новият език е в менюто.

**Един език за всичко.** Изборът на език в страничната лента сменя интерфейса **и** всичко, което Claude чете и пише: `CLAUDE.md`, скиловете, шаблоните на страниците, началните страници и промптовете, които приложението праща към Claude. Езиковите пакети са в `content/<код>/` (включени са английски `en` и български `bg`); ако за език има превод на интерфейса, но още няма пакет за съдържанието, се ползва английският. `npm run content -- <код>` инсталира пакет от командния ред. Страниците, които вече са в wiki-то, не се пренаписват. Нов език на съдържанието (например полски): копирай `content/en/` като `content/pl/` и преведи всички файлове, включително `prompts.json` (английски текст → превод, със същите `{0}`); добави `locales/pl.json` за интерфейса; после избери полски от менюто. Настройката „Език на индексиране“ → „Страниците на езика на източника“ пише страниците на всеки източник на неговия език.

## Правила за сортиране

| Файл | Папка |
|---|---|
| PDF над 80 страници, EPUB, MOBI, DJVU | `books/` |
| PDF до 80 страници | `papers/` |
| DOCX, ODT, RTF, TXT | `articles/` |
| HTML, MD със `source: http…` (Obsidian Web Clipper) | `web/` |
| MD без източник | `notes/` |
| XLSX, CSV, TSV, JSON (XLS и ODS се сортират, но за извличане ги запиши като XLSX) | `data/` |
| PNG, JPG, SVG, HEIC | `images/` |
| всичко друго | `other/` |

Дубликатите (същото съдържание, друго име) се засичат по SHA-256 и остават в inbox.

## Граници на модела

- Работи най-добре до около 100 до 200 източника. След това навигацията само през `index.md` отслабва и си струва да се добави търсачка като QMD (Lutke, n.d.).
- Сканираните PDF минават през OCR автоматично при „Надгради“ или с `npm run extract -- --force --ocr <файл>`. Разпознаването може да греши в имена и специални термини; страници с много грешки са с `confidence: low`.
- Критиката от общността е основателна: подреждането и свързването са част от ученето. Затова ingest по подразбиране спира и обсъжда ключовите изводи с теб, преди да пише.
