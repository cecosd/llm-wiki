# Обикновен и защитен режим

Библиотеката ползва много пакети, писани от други хора. Ако един от тях някога бъде подменен със зловреден, с обикновени права той може да чете и праща файловете ти. **Защитният режим** ограничава докъде стига програмата. Това е предпазна мярка за рядкия лош случай, не нещо, за което да мислиш всеки ден.

Режимът се вижда долу в менюто и се сменя в [Настройки → Режим и безопасност](#/settings/mode). Смяната рестартира сървъра за няколко секунди.

## Двата режима

| | Обикновен | Защитен |
|---|---|---|
| Файлове, до които стига програмата | Всички на акаунта ти | Само папката на библиотеката |
| Сканирани PDF (вграден OCR) | Работи | Само при силна защита |
| Резервни копия към други папки | Работят | Изключени (папките са извън проекта) |
| За кого | Ежедневна работа | Когато работиш с чужди файлове или искаш повече спокойствие |

## Два вида защита

Типът се избира сам според системата, **без да иска WSL**.

### Силна защита (bubblewrap)

Само Linux и WSL с инсталиран `bubblewrap` (`sudo apt install bubblewrap`). Програмата се пуска в „клетка“:

- вижда само папката на библиотеката; кодът ѝ е само за четене;
- не вижда `~/.ssh`, други проекти, дисковете на Windows, ключовете на други програми;
- не може да пуска програми на Windows през WSL.

### Основна защита (права на Node.js)

За Windows, macOS и Linux без bubblewrap. Пуска се със `node --permission` (Node.js 24 или по-нов): Node.js забранява четене и запис извън папката на библиотеката (запис има само в `raw/`, `wiki/`, `drafts/`, `outputs/` и файловете с настройки). Помощните Node процеси (извличане на текст) получават същите ограничения.

Това е **предпазен колан, не клетка**:

- програмите, които сървърът пуска (`git`, Claude Code, `ocrmypdf`, `pdftotext`), работят с нормалните ти права;
- документацията на Node.js изрично казва, че режимът не спира решително зловреден код;
- вграденият OCR е изключен, защото иска вграден модул (add-on).

## От какво НЕ пази никой от режимите

- Мрежата е отворена (нужна е за модела и за „Добави статия“). Зловреден пакет би могъл да изпрати това, до което има достъп, тоест самата библиотека.
- Файловете в `raw/` и `wiki/` могат да се променят от програмата: ползвай „Върни“ и резервни копия.
- Грешките на ИИ в страниците.

## Винаги включено (и в двата режима)

- Сървърът слуша само на `127.0.0.1`.
- Проверка на `Host`, произхода на заявката и задължителна заглавка: друг сайт не може да чете библиотеката ти.
- Политика за съдържание в страниците (без вграден код и чужди адреси); HTML от източниците се чисти.
- Парола по желание.

## Честно за превключвателя

Бутонът за смяна е удобство за теб, не бариера срещу код, който вече работи в сървъра: такъв код би могъл да поиска смяна на режима. Ако допускаш подобен риск, пускай програмата само със силна защита и не ползвай зловредни файлове. Подробности за пакетите има в `SECURITY.md`.

## От терминала

```
npm run app -- --safe      # прекият път с защитен режим (запомня се)
npm run app -- --normal
npm run serve:safe         # само bubblewrap (Linux, WSL)
npm run sandbox:check      # проверка отвътре
```
