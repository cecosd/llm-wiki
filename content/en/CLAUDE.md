# Personal library: LLM Wiki

This is a personal knowledge base following Andrej Karpathy's pattern (LLM Wiki). The human chooses what goes in; you (the LLM agent) read, summarize, link and maintain everything in `wiki/`. The human rarely writes in `wiki/` by hand.

Analogy: `raw/` is the source code, you are the compiler, `wiki/` is the compiled result, `lint` is the tests, and the questions are the runtime.

## Start of every session and the owner's rules

**At the start of every session read `CLAUDE.md` (this file) and `PROJECT-HISTORY.md`.** The second describes what has been done on the project, how the code is organized and which files change for each kind of goal (it is written in Bulgarian). If `CLAUDE.local.md` exists (personal, outside git), read it too: it holds the owner's personal preferences.

General rules for working with the owner (they apply to every session unless they explicitly ask otherwise):

- **First ask what they think.** When they ask a question, do not hand over a ready answer: first ask what they themselves think and only then answer. When the task is clear and actionable (e.g. "fix it"), carry it out directly.
- **Reasoning and sources.** Every answer has a reason why and states what the information comes from (documentation, code in the project's files, publications).
- **Always cite in APA style.**
- **No em dash (—)** in any texts, answers or pages.

## Structure

```
raw/                 Layer 1: source files. NEVER change their content.
  inbox/             New files that are not sorted yet.
  books/             Books (PDF > 80 pages, EPUB, MOBI).
  papers/            Scientific papers and short PDFs.
  articles/          Articles, essays, DOCX/ODT/TXT.
  web/               Clipped web pages (MD/HTML).
  data/              Tables and data (XLSX, CSV, JSON).
  notes/             The owner's own notes.
  images/            Images, diagrams, scans.
  other/             Everything else.
  .extracted/        Text versions of the raw files (generated by `npm run extract`). You read from here.
  manifest.json      Registry: path, sha256, date added, whether it is processed.
wiki/                Layer 2: the pages you maintain.
  index.md           Catalog of everything. You read it FIRST in every operation.
  log.md             Chronological journal. You only append at the end.
  overview.md        Overview of the whole library: main topics and how they connect.
  sources/           One page for every processed raw file.
    chapters/        For books: one page per chapter (drill down).
  concepts/          Concepts, theories, methods (e.g. entropy.md).
  entities/          People, organizations, tools, works.
  topics/            Topic hubs that group concepts and sources.
  comparisons/       Comparisons (e.g. rag-vs-llm-wiki.md).
  questions/         Saved answers to valuable questions.
  _templates/        Templates for every type of page.
outputs/             Reports, lint results, dated exports.
drafts/              Texts from "Write with the wiki" (.md with frontmatter). Outside wiki/ and outside processing; edited freely. `.history/` keeps versions, `.trash/` the deleted ones.
scripts/             Node.js tools (see "Tools").
content/             Language packs of this file, the skills, the agent, the templates and the starter pages (see "Content language").
CLAUDE.md            Layer 3: this schema.
```

## Content language

The language of the wiki pages is the **content language** of the library (English or Bulgarian, or any language that has a pack in `content/`; set from the language menu or with `npm run content -- <code>`). This file, the skills in `.claude/skills/`, the agent in `.claude/agents/`, `wiki/_templates/` and `scripts/starter/` are the installed copy of the pack in `content/<code>/`. To change them permanently edit the pack, then run `npm run content` again. The language menu in the sidebar switches the interface and this content language together.

Technical markers in the extracted text keep their historical names, whatever the language: `<!-- стр. N -->` is a PDF page marker ("page"), `<!-- раздел N -->` is an EPUB section marker, and `думи:` in the header is the word count. Do not translate or change them: the reader and the scripts depend on them.

## Language rules

- Write the pages in **English**. Leave the original terms in parentheses at first use: "critical thinking (kritisches Denken)" when the source is in another language.
- Do not use the em dash (—). Use a comma, a colon, parentheses or a new sentence.
- Bibliographic records are in **APA 7** style.
- File names are in Latin, kebab-case: `entropy.md`, `smith-john.md`. The title in frontmatter can be in any script.

## Frontmatter (mandatory for every page in wiki/)

```yaml
---
title: Title of the page
type: source | chapter | concept | entity | topic | comparison | question
tags: [physics, thermodynamics]
sources:                      # raw paths the page relies on
  - raw/books/smith-2020-example.pdf
related:
  - "[[entropy]]"
created: YYYY-MM-DD
updated: YYYY-MM-DD
confidence: high | medium | low
---
```

Additional fields only for `type: source`:

```yaml
raw_path: raw/books/smith-2020-example.pdf   # the exact path; scripts use it to know the file is processed
format: book | paper | article | web | dataset | note | image
authors: ["Smith, J."]
year: 2020
apa: "Smith, J. (2020). *An example book*. Example Press."
status: read | skimmed | to-read
emphasis: "One sentence: what the source itself puts the weight on"
lang: en            # language of the source (code) when it differs from the library; filled in by "index in the original language"
original_title: "Structural family therapy"   # title as in the source (optional)
page_offset: 0      # books only: PDF page minus printed page (see "Page numbers")
depth: 2            # processing level; 2 = the current standard (emphasis, chapters, PDF pages). Missing = old processing
area: Physics       # area of knowledge: free text of 1 to 3 words; exactly one per source
```

Additional fields for `type: chapter` (file `wiki/sources/chapters/<book-slug>-ch03.md`):

```yaml
book: "[[smith-2020-example]]"   # the source page of the book
chapter: 3                        # sequence number
pages: "47-66"                    # PDF pages (as in the markers <!-- стр. N -->)
raw_path:                         # NOT filled in: only the book has a raw_path
```

**Exception:** when a book is assembled from several separately uploaded files (each file is one chapter; see "Merging separately uploaded sources into a book" below), `raw_path` and its own `page_offset` are written on the chapter, not on the book, because every chapter has its own raw file with its own numbering. In that case the book's source page has no `raw_path`; `npm run merge-sources` does this automatically.

Additional field for `type: entity`: `kind: person | organization | tool | work | place`.

Additional field for concept and entity pages: `aliases: [Tchaikovsky, Chaikovsky, Pyotr Tchaikovsky]`: other spellings and translations of the same name or concept. Search and paths use them, so one and the same person does not split into two pages.

## Rules for links

- All internal links are `[[wikilinks]]` by the file name without `.md`: `[[entropy]]`, `[[smith-john|John Smith]]`.
- Every claim in a concept/entity/topic page must be traceable to a source page. Put the source at the end of the sentence: `([[smith-2020-example]], p. 201)`. If the book has chapters, point to the chapter: `([[smith-2020-example-ch03]], p. 53)`. This way the reader can go down from the concept to the chapter and to the page itself.

### Page numbers

- `p. N` is always **the PDF page number** from the marker `<!-- стр. N -->` in `raw/.extracted/`. The interface opens exactly that page in the reader, so the number must match the marker, not the printed number.
- For books record `page_offset` in the source page: the difference between the PDF and the printed number (if at `<!-- стр. 61 -->` the text shows printed number 53, `page_offset: 8`). This way citations in articles can later be converted to printed pages for APA.
- EPUB has no pages: use `sect. N` from the marker `<!-- раздел N -->`.
- Without a marker, or if you are not sure: `p. ?` and `confidence: low`.
- Every new page must have at least one incoming link (from index.md, from a topic hub or from a related page). Orphans are not allowed.
- When two sources contradict each other, do not choose silently. Add a section `## Contradictions` and describe the two positions with their sources.

## Workflows

### Inbox (sorting and extraction)

1. Run `npm run inbox`. The script moves the files from `raw/inbox/` to the right folder and records them in manifest.json.
2. Run `npm run extract`. The script creates text versions in `raw/.extracted/`.
3. Run `npm run status` and show the human what is waiting for processing.

### Ingest (processing a source)

**Incremental, not from scratch.** Every raw file is read once. `npm run pending` says which files are new; process only those. Do not walk through `raw/` and do not open the originals or the `.extracted` versions of already processed sources, even when you update related pages: for them use the source pages in `wiki/sources/`. Reprocessing only on an explicit "reprocess <file>".

1. Read `wiki/index.md` to know what already exists.
2. Read the text version from `raw/.extracted/` (for images: the file itself). For long books read chapter by chapter; do not load the whole book at once.
3. **The emphasis is determined by the source itself, not by the human.** Do not ask questions. Determine it from: the author's stated purpose (introduction, preface, abstract), which chapters are most developed, which concept is central and which one the text keeps returning to. Write it in the field `emphasis` and in the section `## Emphasis of the source` with 2 to 4 sentences of reasoning. If the human explicitly named an emphasis, it takes precedence.
4. Create `wiki/sources/<slug>.md` from the template `_templates/source.md`. Slug: `<surname-of-first-author>-<year>-<keyword>`. In `raw_path` copy the path exactly as `npm run pending` gives it. Set `depth: 2`.
4a. **Books only (`format: book`):** create one page per chapter in `wiki/sources/chapters/` from the template `_templates/chapter.md`. Slug: `<book-slug>-ch01`, `-ch02` and so on (two digits). Every chapter: a summary, key ideas with `p. N`, the concepts it introduces. In the source page a section `## Chapters` lists all chapters as `[[...-ch01]]` in order. A preface and appendices are included only if they have substantial content.
5. Update the existing concept/entity/topic pages that the source touches (usually 5 to 15). Add, do not overwrite: new knowledge is merged into the existing text, with a citation.
6. Create new concept/entity pages only for things that appear substantially (not for every mention). **Before creating a page for a person or a concept, check whether one already exists under another spelling** (transliteration: Tchaikovsky, Chaikovsky; translation: entropy, Entropie). Search `wiki/entities/` and `wiki/concepts/` by title, slug and `aliases`, and by sound, not only letter by letter. If one exists, merge the new knowledge into it and add the other spelling to `aliases`; do not create a second page. Write the author names in `authors` identically across all sources: use the spelling already recorded if the author is there.
7. If the source contradicts something in the wiki, mark it in a section `## Contradictions` and in the log.
8. Update `wiki/index.md` (new pages in the right section, with a one-line description).
9. Update `wiki/overview.md` if a new big topic appears.
10. Add an entry to `wiki/log.md` (format below).
11. Run `npm run lint:quick` and fix any broken links.

For tables (`format: dataset`): describe the columns, the range, the units, what the data show and what questions they can answer. Do not copy the data.

### Chapters for an already processed book

On a request "split <book> into chapters" (or the skill `wiki-chapters`): read the source page, then the `.extracted` text of the book **chapter by chapter**, and create the pages in `wiki/sources/chapters/` as in step 4a. Update the section `## Chapters`, add `page_offset` and redirect the citations in the concept pages from the book to the corresponding chapter where it is clear which one it is. An `ingest` entry in the log.

### Upgrading an old source (`wiki-upgrade`)

A source without `depth: 2` was processed to an older standard. The upgrade **adds**, it does not start over: it does not create a second source page, does not duplicate concepts and **carries over verbatim** the section `## My notes`.

1. Read the source page and its chapters (if any), then the `.extracted` text chapter by chapter.
2. Complete the book: `emphasis` and `## Emphasis of the source`, `page_offset`, `## Chapters`, key ideas with PDF pages. Set `depth: 2` and `upgraded: YYYY-MM-DD`.
3. Chapters: create the missing ones, update the existing ones (no new files for chapters already described).
4. Bring all citations to this source in the wiki (`grep` for its slug) to the chapter and the PDF page.
5. Concepts: add the missed ones that the source develops substantially; update the existing ones with a citation to the chapter. Do not duplicate: check index.md and `wiki/concepts/` for synonyms.
6. Contradictions with other sources: a section `## Contradictions`, use their source and chapter pages.
7. An `upgrade` entry in the log.

### Merging separately uploaded sources into a book (`merge-sources`)

When the chapters of a book were uploaded and processed as separate files (each chapter became an independent `source` page), they can be merged into the standard book+chapters model with `npm run merge-sources -- "Book title" <slug1> <slug2> [...]` (preview; add `--apply` to apply) or from the button "Merge separate sources into a book with chapters" in the "Sources" collection in the interface. The order of the slugs determines the numbering of the chapters.

The script: turns every chosen source into `wiki/sources/chapters/<new-slug>-chNN.md` (keeps `raw_path`, tags, `related`, content), creates a new source page for the book, redirects all `[[links]]` to the chosen slugs, archives the original pages in `outputs/merged/`, rebuilds `index.md` and writes a `refactor` entry in `log.md`. The APA record, the authors, the year and the `area` of the new book are taken from the chapters as a starting point: always review and fix them by hand after merging (the new page has `confidence: low` precisely for that reason).

### Synthesis across sources (`wiki-synthesis`)

Reads only wiki pages. Optionally limited to a tag or a topic.

1. From index.md and the concepts find those that **at least two different sources** point to.
2. For each such concept where the authors differ substantially: a page in `wiki/comparisons/` (a table by dimensions, conclusions, citations to the chapters).
3. Topic hubs in `wiki/topics/` for the groups of concepts that do not have a hub yet.
4. Update `overview.md`: the main lines in the library and how they connect.
5. Gaps: concepts with one source, claims with `confidence: low`, unanswered questions. Write them to `outputs/synthesis-YYYY-MM-DD.md` with recommendations on what to read.
6. A `synthesis` entry in the log.

### Query (a question to the library)

1. Read `wiki/index.md` and choose the relevant pages. Do not load the whole wiki.
2. Read them and synthesize an answer with `[[wikilinks]]` citations.
3. If the wiki is not enough, say so clearly and point to the raw file that may contain the answer.
4. If the answer is new and valuable, offer to save it in `wiki/questions/<slug>.md`.

### Reviewing a text against the library (`wiki-review`)

On "review the article", "check the citations" or from the button "Review with the wiki" in "Write with the wiki": follow the skill `wiki-review`. In short: every citation is checked page by page in `raw/.extracted/` (the printed page plus `page_offset` gives the marker `<!-- стр. N -->`), APA 7 is corrected (chapters in edited books by the chapter author, "et al." for three or more authors, translations, secondary citations, books without printed pages by chapter), unsupported claims are supported from the library or marked, and the sentences are made natural (on average 14 to 18 words, none above about 35). Nothing is invented: what only the author knows is written as `[FILL IN: ...]`. The review does not write in `wiki/`: the corrected text and the report go to the person (in the interface the report is kept in `drafts/.reviews/`).

### Lint (health check)

1. Run `npm run lint`. The script catches the mechanical problems: broken links, orphans, missing frontmatter, pages outside index.md, unprocessed raw files.
2. Then do the semantic check by hand:
   - contradictions between pages;
   - outdated claims superseded by newer sources;
   - concepts that are mentioned often but have no page of their own;
   - pages with `confidence: low` that have not been updated for a long time;
   - topics where sources are missing (reading gaps).
3. Write the result in `outputs/lint-YYYY-MM-DD.md` and add an entry to the log.

## Format of log.md

```markdown
## 2026-10-28 ingest: Smith (2020) An Example Book
- New: [[smith-2020-example]], [[entropy]], [[second-law]]
- Updated: [[smith-john]], [[thermodynamics]], [[topics/statistical-physics]]
- Contradictions: none
- Note: ...
```

Entry types: `ingest`, `upgrade`, `synthesis`, `query`, `lint`, `refactor`, `inbox`.

## Format of index.md

The sections are: Overview, Topics, Concepts, People and organizations, Sources (grouped by format), Comparisons, Questions. Every line: `- [[slug]]: one-line description`.

The page "Write with the wiki" (`#/write`) writes a text on a topic from the library in one of five kinds: a scientific article (abstract, introduction, theoretical framework, analysis, discussion, conclusion, bibliography in APA 7), an essay, a popular science article, a literature review or fiction (no citations in the text itself; the sources are listed under "Based on"). It works locally (scientific article only) or with Claude on three levels, with a creativity from 1 to 5 that changes the style and the interpretation but not the facts: those and the citations always come only from the library. There is also a blank document that the person writes, with help paragraph by paragraph (rewrite, new paragraph) and continuing; the kind, the creativity and the scope (areas and topics) are kept in the frontmatter of the draft. In the editor "Review with the wiki" runs the skill `wiki-review` on the whole text: "Correct the text" puts the corrected text in the editor without saving, "Report only" leaves the text unchanged; the report is kept in `drafts/.reviews/<id>/`. Do not write in `drafts/` during ingest.

The page "Add an article" (`#/find`) accepts a DOI or an address starting with https://, downloads the PDF (or the text of the page, or only the abstract if the full text is not free) into `raw/inbox/` and starts sorting and extraction. Then the human chooses a mode (economy, balanced, best) and an indexing language for this file; processing with Claude starts after the tokens and the price are confirmed. Downloaded web texts have frontmatter with `source:` and go to `raw/web/`. There is no catalog search. Do not change the files in `raw/`.

The human can rename a page (double-click on the title) and edit a selected paragraph by hand. This changes only `title` and the text: the file name and all `[[links]]` stay the same, so do not touch them in such changes. A file the human does not want is moved to `raw/.trash/` (unprocessed) and is never processed.

Before every action with Claude the interface shows approximate tokens and price (the setting "Show tokens and cost…" on the home page). The real cost of every processing is recorded in `outputs/.agent-history.json` (`costUsd`, `tokens`).

**Areas.** Every source has a field `area` (one area, no predefined list). Before inventing a new area, use an existing one with the same meaning (see `area` in the other source pages). Chapters inherit the area of their book through `book`, so `area` is not written on a `chapter`. Concepts, people and topics do not have an `area` by default: their area is computed from the sources that cite them (the area with the most citations wins). A concept stays ONE page even if it is used in several areas; do not make a second page "for another area". The page "Areas" (`#/areas`) determines areas of old sources, renames and merges areas; "Learn by question" and "Write with the wiki" can be limited to chosen areas and topics.

**Indexing language.** The setting on the home page chooses: only the library language; the library language plus the original terms (in `aliases`, `tags`, `lang`, `original_title`); or pages in the language of the source. When it is set, the instruction comes with the prompt and takes precedence over the rule "write in English" only for this setting.

## Modes and the chapter reader

The model for reading chapters and the model for writing the pages are chosen separately in the interface (Haiku, Sonnet or Opus). If they differ, chapters are read by `chapter-reader` with the chosen model; if they are the same, you read them yourself. The ready modes are only a quick choice. The button in the interface runs the processing in one of three modes: "Economy" (Sonnet edits, the subagent `chapter-reader` on Haiku reads the chapters), "Balanced" (Sonnet) or "Best" (Opus). In economy mode, for every chapter of a book call `chapter-reader` with the path and range of the chapter and work from its notes; read only the table of contents and the introduction yourself. The judgement (emphasis, merging concepts, contradictions) always stays yours.

## Model and provider

Which model works is chosen in "Settings → Model" (the `ai` key in `library.config.json`; API keys are in `.library-secrets.json`). There are three ways of working:

- **Agent (Claude Code):** as described in this file, with the skills. Besides a Claude subscription or API key, Claude Code can work with a model of another provider that accepts the Anthropic format (DeepSeek, local Ollama and others). Then Haiku, Sonnet and Opus in the interface are the three models chosen for that provider. The rules in this file apply the same way.
- **Without tools (API, local model):** the server (`scripts/pipeline.js`) gives the model the text in parts and writes the pages itself from the templates, with the same rules: emphasis from the source, chapters, citations to the chapter and the PDF page, extending concepts, `## Contradictions`, index and log. The model gets only text, so unknown `[[links]]` become plain text.
- **By hand (copy and paste):** the same as without tools, but every request is copied into a chat in the browser and the answer is pasted back into the interface.

Log entries from processing without tools have the note "processed without tools by …". Such pages can be upgraded later with a stronger model ("Upgrade").

## Prohibitions

- Do not change, rename or delete files in `raw/` (except the move from the inbox, which the script does).
- Do not invent citations, pages or years. If you do not know, write `p. ?` and `confidence: low`.
- Do not copy long passages from the sources. Paraphrase; a quote of up to 1 to 2 sentences, in quotation marks, with a page.
- Do not delete pages from the wiki without explicit consent. To merge duplicate pages use a `refactor` entry in the log.
- Do not read `.library-secrets.json`, `.library-auth.json` and `library.config.json`: they hold the keys and the settings of the human.
